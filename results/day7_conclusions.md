# День 7 — Сохранение контекста: выводы

Код: `day7_memory.py`. Модель: `deepseek-v4.1-flash` (OpenCode Go). Прогон `--demo`:
`results/day7_20261115_231905.md` / `.json` (шаги и весь файл истории). Плюс ручной прогон в чате для видео
(сессия `default`): тот же сценарий «вопрос с инструментами → `/exit` → новый запуск → вопрос по памяти».
До живого прогона механика проверена на заглушке API: перезапуски, `/reset` и `--new` с архивом, обрезанный
и битый файл истории, падение API, контрольный вопрос в диалоге без истории (ответ «не знаю»).

## Как устроено

- `PersistentAgent` наследует `Agent` из Дня 6: цикл с инструментами тот же, добавлено хранилище
  `HistoryStore` — JSON-файл `memory/<сессия>.json`.
- В файл пишется весь список `messages` в формате запроса к API: `system`, `user`, `assistant` с `tool_calls`
  и `reasoning_content`, `role: "tool"` с результатами. Отдельно — `session_id` для заголовка `x-opencode-session`
  и статистика по ходам (в API не уходит).
- Сохранение — после каждого завершённого хода, атомарно (временный файл + `os.replace`). Упал API или ход прерван
  Ctrl+C — история откатывается к началу хода, файл не меняется.
- Загрузка — при старте: история подставляется в агента как есть, незавершённый ход в конце файла отбрасывается.

## Результаты: 3/3 проверки

Каждый запуск — отдельный процесс `python day7_memory.py --session demo_… "<запрос>"`, общего у них — только файл.

| Запуск | Сообщений до → после | Вызовы инструментов | Запросов к модели | Токены вход/выход | Время, с |
|---|---|---|---|---|---|
| 1 — «Который час в Токио? И сколько рублей стоят 150 долларов?» | 0 → 6 | `get_current_time(Asia/Tokyo)`, `convert_currency(150, USD, RUB)` | 2 | 1 659 / 169 | 7.7 |
| 2 — перезапуск: «какое точное время, с секундами, вернул инструмент?» | 6 → 8 | — | 1 | 1 034 / 65 | 3.9 |
| 3 — перезапуск: «прибавь 10% к рублёвой сумме из первого вопроса» | 8 → 12 | `calculator(12225 * 1.1)` | 2 | 2 350 / 96 | 7.8 |

- **Помнит именно результат инструмента, а не свой ответ.** В запуске 1 модель ответила «05:19» — без секунд.
  В запуске 2 она назвала `05:19:09`: секунды есть только в сообщении `role: "tool"`, значит после перезапуска
  модель получила историю целиком, включая результаты вызовов. Инструменты при этом не вызывала.
- **Результат прошлого вызова стал аргументом нового.** В запуске 3 калькулятор получил `12225` — число из
  результата `convert_currency` двумя запусками раньше. Ответ: `13 447,50 ₽`.
- **История продолжается, а не начинается заново.** Для каждого шага проверено, что прошлые сообщения в файле
  не изменились и к ним добавились новые (0 → 6 → 8 → 12). `session_id` один на все три процесса.
- **Ручной прогон в чате — то же самое.** Между ходами — выход из программы и новый запуск (71 с).
  Первый ответ — «05:16», после перезапуска на «какое точное время вернул инструмент?» — `05:16:38`, как в результате
  `get_current_time`. При старте агент показал «восстановлено 6 сообщений: 1 ход, 2 результата инструментов».

## Наблюдения

- **Память = контекст, который отправляется заново.** У модели нет своей памяти между запросами: «помнить»
  значит прислать ей всю историю. Поэтому вход растёт с длиной диалога: вопрос по памяти без единого
  инструмента стоил 1 034 входных токена против 726 у вопроса без инструментов в День 6 — около 300 токенов
  на один восстановленный ход с двумя вызовами. Длинный диалог со временем придётся сжимать или обрезать.
- **Сохранять нужно ровно то, что уходит в API.** Если записывать только тексты реплик, после перезапуска
  пропадут `tool_calls` и результаты — модель не вспомнила бы `05:19:09`. А обрезанная история, где у `assistant`
  есть `tool_calls`, но нет ответов `role: "tool"`, API отклоняет — отсюда проверка хвоста при загрузке.
- **`reasoning_content` из прошлых ходов тоже в истории.** В файле три сообщения с рассуждением DeepSeek;
  после перезапуска они уходят в запрос вместе с остальным, и API их принимает.
- **Сохранять — после хода, а не посреди.** Полуготовый ход (вызов инструмента без финального ответа)
  при перезапуске бесполезен и ломает запрос, поэтому запись идёт только после финального ответа, а сама запись
  атомарна: файл истории не бывает наполовину записанным.
- **Сброс не удаляет историю.** `/reset` и `--new` переименовывают файл в `<сессия>_<время>.json` — прошлый диалог
  можно вернуть, переименовав обратно.

## Итог

Агент Дня 6 стал агентом с долгой памятью: история хранится в JSON целиком, вместе с вызовами инструментов
и их результатами, и при запуске загружается обратно. После перезапуска `deepseek-v4.1-flash` продолжил диалог
как ни в чём не бывало: назвал точное значение из результата инструмента прошлого запуска и использовал его
в новом вызове. Плата — вход по токенам растёт с каждым ходом, потому что вся история отправляется заново.
