# Неделя 2 · День 1 — Первый агент: выводы

Код: `day6_agent.py`. Модель: `deepseek-v4.1-flash` (OpenCode Go), function calling через поле `tools`
OpenAI-совместимого API. Прогон: `results/day6_20261115_211728.md` / `.json` (вся история сообщений).
Повтор `results/day6_20261115_222206.md` / `.json` — снова 3/3, те же инструменты с теми же аргументами,
вход по токенам почти тот же (726 / 1 524 / 2 614); различаются только формулировки ответов.
До живого прогона цикл проверен на заглушке API: обычные сценарии, ошибки инструментов
(неизвестный инструмент, битый JSON, недопустимое выражение), упор в `--max-steps`, падение API посреди цикла.

## Как устроен агент

- `Agent` — отдельный класс. Хранит историю диалога, реестр инструментов и предел шагов. Об интерфейсе не знает:
  шаги цикла отдаёт в колбэк `on_event`, CLI их печатает.
- `Agent.run(запрос)` — цикл: запрос к модели со схемами инструментов → если в ответе есть `tool_calls`,
  код выполняет каждый вызов и кладёт результат в историю (`role: "tool"`, `tool_call_id`) → снова запрос.
  Цикл заканчивается, когда модель отвечает без `tool_calls`.
- Инструменты — обычные функции на несколько строк, описанные JSON-схемой: `get_current_time`, `calculator`
  (разбор через `ast`, без `eval`), `convert_currency` (курс зашит в код).

## Результаты: 3/3 сценария

| Сценарий | Вызовы инструментов | Запросов к модели | Токены вход/выход | Время, с |
|---|---|---|---|---|
| без инструментов — «чем агент отличается от одного вызова модели» | — | 1 | 726 / 75 | 4.7 |
| один инструмент — «Который час сейчас в Токио?» | `get_current_time(Asia/Tokyo)` | 2 | 1 524 / 77 | 8.6 |
| два подряд — «150 долларов + комиссия банка 3,5%» | `convert_currency(150, USD, RUB)` → `calculator(12225 * 1.035)` | 3 | 2 598 / 212 | 10.3 |

- Модель сама выбрала инструмент и аргументы: из «Токио» сделала часовой пояс IANA `Asia/Tokyo`,
  из «150 долларов» — `USD`/`RUB`. На вопрос без нужды в инструментах ничего не вызвала
  (так же в чате — «Что первично, курица или яйцо?»).
- «Подряд» — по-настоящему последовательно: калькулятор вызван на втором шаге с числом `12225`,
  которое модель взяла из результата конвертера. Параллельно эти вызовы сделать нельзя — второй зависит от первого.
- Финальный ответ построен на результатах инструментов: `12 652,875` округлено до `12 652,88 ₽`, курс `81,5` —
  из конвертера. Мелочь: размер комиссии (`427,88 ₽`) модель для пояснения посчитала сама, без калькулятора,
  хотя системный промпт просит все вычисления делать через него. Число верное.

## Наблюдения

- **Цена инструментов — даже когда они не нужны.** Схемы трёх инструментов и системный промпт — около 700 входных
  токенов в каждом запросе. На простой вопрос без инструментов ушло 726 токенов входа против нескольких десятков
  у голого вызова в День 1.
- **Каждый шаг — полный запрос с растущей историей.** В сценарии с двумя инструментами вход рос 739 → 892 → 967:
  модель каждый раз получает всю историю с вызовами и результатами. Суммарно 2 598 входных токенов —
  в 3,5 раза больше, чем на вопрос без инструментов, и время почти тоже кратно числу шагов (≈3–5 с на шаг).
- **Рассуждение нужно возвращать модели.** DeepSeek V4.1 Flash на первом шаге отдаёт `reasoning_content`
  («Compute 150 USD to RUB, then multiply…») — план на оба вызова сразу. Агент кладёт его обратно в историю
  вместе с `tool_calls`: в режиме рассуждения с инструментами DeepSeek ждёт его обратно в пределах хода,
  иначе модель теряет свой план между шагами.
- **`content` в ответе с вызовами пустой (`null`).** Клиент из прошлых дней брал только текст — для агента пришлось
  отдавать ещё `tool_calls` и исходное сообщение. Старые скрипты от этого не изменились.
- **Ошибки инструментов — это данные для модели, а не исключение.** Неизвестный инструмент, битый JSON аргументов,
  деление на ноль или `__import__` в калькуляторе возвращаются модели как `{"error": ...}`, и она может
  исправиться на следующем шаге. Цикл ограничен 8 запросами к модели за ход, чтобы агент не зациклился.
- **Windows:** `zoneinfo` без пакета `tzdata` не знает часовых поясов — он добавлен в `requirements.txt`.

## Итог

Агент — это не один вызов API, а цикл с состоянием: модель решает, что вызвать, код выполняет,
результат возвращается в историю, и так до финального ответа. На трёх сценариях `deepseek-v4.1-flash`
правильно различил «инструменты не нужны / нужен один / нужны два последовательно» и построил ответ на их результатах.
Плата за это — входные токены на схемы инструментов в каждом запросе и время, растущее с числом шагов.
