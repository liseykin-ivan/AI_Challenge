# Промт: публикация в репозиторий

Опубликуй изменения проекта AI Challenge в GitHub (`liseykin-ivan/AI_Challenge`).
Коммит и ветка создаются git'ом в папке проекта на компьютере. Отправка идёт из облачного окружения сессии:
у git на компьютере нет учётных данных GitHub, а у облака они есть.
Коммиты переносятся в облако bundle-файлом, поэтому на GitHub уходят ровно те же коммиты (те же хеши).

Режимы:
- **Публикация дня** — по умолчанию, когда просят опубликовать день или результаты задания.
  Коммит в `main` и ветка `week_<N>/day_<M>` на том же коммите; обе ветки отправляются одной атомарной
  операцией (уходят вместе или не уходят вовсе). Номер дня — из последнего `tasks/week_*_day_*.md`,
  если пользователь не назвал другой.
- **Обновление** — правка вне дня (инструменты, README, промпты): коммит только в `main`, без ветки дня.

Если какая-то проверка ниже не прошла — остановись, ничего не обходи и не исправляй силой,
сообщи пользователю причину и спроси, что делать.

## 1. Подготовка на компьютере (в папке проекта)

1. До первой git-команды попроси разрешение на удаление в папке проекта: git удаляет свои lock-файлы,
   без этого даже `git status` или `git fetch` оставляют `.lock` в `.git`, и следующие команды падают.
2. Состояние репозитория:
   - текущая ветка — `main`;
   - нет незавершённого merge/rebase/cherry-pick (`MERGE_HEAD`, `rebase-merge`, `rebase-apply`, `CHERRY_PICK_HEAD` в `.git`);
   - в `.git` нет `*.lock` (поиск по всей `.git`). Если есть — сообщи их время создания и спроси, удалить ли.
3. `git fetch origin`. `origin/main` должен уже входить в историю локального `main`
   (`git merge-base --is-ancestor origin/main main`). Если локальный `main` отстал или разошёлся с GitHub —
   остановись и сообщи.
4. Для публикации дня: ветки `week_<N>/day_<M>` нет ни локально, ни на GitHub (`git ls-remote --heads origin <ветка>`).
   Если она уже есть — день, скорее всего, уже опубликован: сообщи и ничего не делай.
5. Для публикации дня проверь, что результаты на месте: код, `tasks/week_<N>_day_<M>.md`, отчёты прогонов
   и выводы в `results/`, раздел дня в README (и ссылка на выводы).
6. Удали из папки проекта временные файлы (бандлы, тестовые копии, черновики) — в коммит попадёт всё,
   что не исключено `.gitignore`.
7. `git add -A`, затем проверь, что войдёт в коммит (`git diff --cached --stat`):
   - есть что коммитить;
   - нет `.env`, `.venv/`, `__pycache__/`, `*.bundle` и файлов больше 20 МБ;
   - в изменениях (`git diff --cached`) нет значений ключей из `.env` (переменные с KEY/TOKEN/SECRET в имени).
     Сверяй программно и сами ключи не выводи.
   Покажи пользователю список файлов. Если в нём есть лишнее — остановись.
8. Сообщение коммита запиши в файл **вне** папки проекта, в стиле прошлых дней:
   первая строка `День <M>: <что сделано>` (для обновления — коротко, что изменено), пустая строка,
   2–5 строк о содержимом, затем строки атрибуции (Co-Authored-By и др.), если они заданы в сессии.
9. `git commit -F <файл>`. Если `user.name`/`user.email` не настроены, возьми их из последнего коммита
   (`git -c user.name=... -c user.email=... commit`).
10. Для публикации дня: `git branch week_<N>/day_<M>` — на только что созданном коммите.

## 2. Отправка из облака

1. На компьютере создай bundle в корне проекта (иначе его не перенести в облако):
   `git bundle create .publish.bundle origin/main..main [week_<N>/day_<M>]` и проверь `git bundle verify`.
2. Перенеси `.publish.bundle` в облачное окружение (stage файла).
3. В облаке нужен клон репозитория с правом push: если его нет — подключи репозиторий
   `liseykin-ivan/AI_Challenge` с доступом push и склонируй (`--depth 1` хватает).
   Затем `git fetch origin main` — чтобы клон знал текущий `origin/main`.
4. `git fetch <bundle> 'refs/heads/*:refs/remotes/bundle/*'`. Проверь:
   - `bundle/main` — потомок `origin/main` (иначе на GitHub появилось что-то новое — остановись);
   - для публикации дня `bundle/week_<N>/day_<M>` указывает на тот же коммит, что `bundle/main`.
5. Отправь одной атомарной операцией:
   `git push --atomic origin bundle/main:refs/heads/main [bundle/week_<N>/day_<M>:refs/heads/week_<N>/day_<M>]`.
   Если push отклонён — остановись и сообщи ответ GitHub; ничего не форсируй (`--force` не использовать).
6. `git ls-remote origin` — `main` (и ветка дня) на GitHub указывают на новый коммит.

## 3. Завершение на компьютере

1. Удали `.publish.bundle` из папки проекта и файл сообщения коммита.
2. `git fetch origin`; для ветки дня — `git branch -u origin/week_<N>/day_<M> week_<N>/day_<M>`.
3. `git status -sb` показывает `main...origin/main` без «ahead/behind», в `.git` нет `*.lock`.

В конце сообщи хеш коммита и название ветки (для обновления — только хеш).
