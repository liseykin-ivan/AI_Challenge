# AI Challenge — CLI-чат с LLM

День 1 (`main.py`): консольное приложение отправляет запрос в OpenCode Go (OpenAI-совместимый API)
через голый `httpx` и печатает ответ, модель, токены и время.
День 2 (`day2_format.py`): сравнение способов управлять форматом ответа — см. [ниже](#день-2-формат-ответа).
День 3 (`day3_reasoning.py`): 4 способа рассуждения × 2 уровня reasoning — см. [ниже](#день-3-разные-способы-рассуждения).
День 4 (`day4_temperature.py`): один запрос при temperature 0 / 0.7 / 1.2 — см. [ниже](#день-4-температура).

## Установка (PowerShell, Python 3.11+)

```powershell
cd C:\Users\user\Desktop\AI_Projects\AI_Challenge
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
notepad .env   # впишите OPENCODE_API_KEY
```

Если `Activate.ps1` запрещён политикой: `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`.

## Запуск

```powershell
python main.py "Привет, кто ты?"
python main.py                              # спросит запрос в консоли
python main.py --model <id> "Привет"        # другая модель (id — из списка ниже)
```

Пример вывода:

```
Привет! Я — ИИ-ассистент...

deepseek-v4.1-flash | токены: 31/24 | 1.42 с
```

При ошибке печатается понятное сообщение, код выхода — 1.

## Проверка доступа без кода

```powershell
$key = ((Get-Content .env) -match '^OPENCODE_API_KEY=')[0].Split('=', 2)[1]
$h = @{ Authorization = "Bearer $key"; "User-Agent" = "ai-challenge-cli/0.1"
        "x-opencode-session" = [guid]::NewGuid().ToString("N") }   # без него OpenCode Go отвечает 400

# список моделей
(Invoke-RestMethod https://opencode.ai/inference/go/v1/models -Headers $h).data.id

# тестовый запрос
$body = '{"model":"deepseek-v4.1-flash","messages":[{"role":"user","content":"ping"}]}'
(Invoke-RestMethod https://opencode.ai/inference/go/openai/v1/chat/completions `
  -Method Post -Headers $h -ContentType "application/json" -Body $body).choices[0].message.content
```

| Файл | Что делает |
|---|---|
| `main.py` | CLI: аргументы, ввод, вывод |
| `llm_client.py` | `LLMClient.chat(messages, **params) -> ChatResult` (текст, `finish_reason`, рассуждение, usage), HTTP и разбор ошибок |
| `config.py` | чтение и проверка `.env` |
| `day2_format.py` | День 2: один запрос с разным уровнем контроля формата |

| `day4_temperature.py` | День 4: 4 задачи (2 с одним ответом, 2 на генерацию) × 3 температуры × 5 прогонов |

## День 2: формат ответа

`day2_format.py` отправляет один и тот же запрос с разным уровнем контроля
и проверяет, может ли код распарсить ответ.

```powershell
python day2_format.py                        # все 7 вариантов × 3 прогона
python day2_format.py --runs 5 --max-tokens 40
python day2_format.py --variants format,schema --runs 2
python day2_format.py --timeout 120 --temperature 0.7 --model <id>
```

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `--runs` | 3 | прогонов на каждый вариант |
| `--variants` | все | список через запятую из таблицы ниже |
| `--max-tokens` | 60 | лимит для `max_tokens` и `schema_max_tokens` |
| `--timeout` | `LLM_TIMEOUT` из `.env` | таймаут одного запроса, с |
| `--temperature` | как у модели | температура для всех вариантов |
| `--model` | `LLM_MODEL` из `.env` | id модели |

| Вариант | Что меняется в запросе |
|---|---|
| `plain` | только вопрос, без системного промта |
| `format` | формат JSON описан словами в системном промте |
| `max_tokens` | `format` + `max_tokens` (по умолчанию 60) |
| `stop` | `format` + просьба закончить маркером `<END>` + `stop=["<END>"]` |
| `json_mode` | `format` + `response_format={"type": "json_object"}` |
| `schema` | `format` + `response_format` со строгой JSON Schema (`strict: true`) |
| `schema_max_tokens` | строгая схема + `max_tokens` |

Каждый ответ проверяется тремя способами: `json.loads` как есть, JSON после чистки
(срезать ```-обёртку и текст вокруг `{...}`) и соответствие схеме (поля, типы, ровно 3 языка).
Для каждого прогона печатаются токены (сколько из них ушло на скрытое рассуждение),
время и `finish_reason`, а для сломанных ответов — причина: например, «лимит max_tokens
съело рассуждение» или «обрезан по лимиту». В конце — итоговая таблица по вариантам.
В `results/` пишутся сырые ответы вместе с рассуждением (`.json`) и отчёт (`.md`),
где для пустого ответа показан хвост рассуждения.
Если провайдер не поддерживает `response_format` или запрос упал по таймауту,
вариант покажет ошибку API, а не уронит скрипт.

Выводы по прогонам на `deepseek-v4.1-flash` — в [`results/day2_conclusions.md`](results/day2_conclusions.md).

## День 3: разные способы рассуждения

`day3_reasoning.py` решает 10 задач с известным ответом (логика, алгоритмы, анализ)
четырьмя способами при минимальном и максимальном рассуждении, проверяет ответы кодом
и строит таблицу «способ × рассуждение → верных / токены / время».

```powershell
python day3_reasoning.py --probe             # сначала: как у модели включается/выключается рассуждение
python day3_reasoning.py                     # полный прогон: 10 × 4 × 2 = 80 решений (~100 запросов)
python day3_reasoning.py --runs 3            # по 3 прогона — устойчивее к случайности
python day3_reasoning.py --set easy          # первый, лёгкий набор задач
python day3_reasoning.py --tasks dice,josephus --methods direct,experts --levels low
python day3_reasoning.py --low reasoning_effort=low --high reasoning_effort=high
python day3_reasoning.py --low thinking.type=disabled --high thinking.type=enabled
```

| Способ | Что в запросе |
|---|---|
| `direct` | только условие |
| `steps` | условие + «Решай пошагово.» |
| `meta` | 1-й запрос: «составь промпт для решения задачи»; 2-й — решение по этому промпту |
| `experts` | аналитик, инженер и критик решают по очереди, у каждого свой ответ, затем итог |

**Наборы задач.** `easy` — первый набор (сёстры Алисы, угол в 3:15, нули в 2026! и т. п.):
`deepseek-v4.1-flash` решил его на 9–10 из 10 при любой настройке, и способы почти не различались.
`hard` (по умолчанию) — задачи, где ответ нельзя вспомнить, а надо считать, перебирать
или замечать ловушку: прямые углы стрелок за сутки, буквы во фразе, рыцари и лжецы вчетвером,
день недели 29.02.2032, пятницы 13-е в 2027, условная вероятность на костях, 7^2026 mod 100,
пятизначные числа с суммой цифр 9, делители 2026², задача Иосифа Флавия.
Эталоны всех задач проверены кодом.

Во всех способах к условию добавлена одна и та же строка формата `ОТВЕТ: <...>`,
чтобы ответ проверялся кодом (числа, день недели, рыцари/лжецы — с нормализацией).

**Уровни рассуждения.** Какой параметр понимает модель, у OpenAI-совместимых провайдеров
разнится, поэтому скрипт сначала делает пробу: шлёт одну задачу с вариантами
`reasoning_effort` (none/minimal/low/high/max), `reasoning.effort`, `thinking`
и смотрит `reasoning_tokens` в ответе. Минимальным уровнем становится вариант с самым
коротким рассуждением, максимальным — с самым длинным. Проба кэшируется
в `results/day3_probe.json` (`--reprobe` — повторить), её выбор можно переопределить `--low/--high`
(форма `ключ=значение`, вложенные — через точку; JSON тоже принимается, но PowerShell 5 съедает в нём кавычки).

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `--set` | `hard` | набор задач: `hard` или `easy` |
| `--runs` | 1 | прогонов каждой пары задача × способ |
| `--workers` | 4 | параллельных запросов |
| `--timeout` | 300 | таймаут запроса, с (высокое рассуждение отвечает долго) |
| `--tasks`, `--methods`, `--levels` | все | подмножество через запятую |
| `--model` | `LLM_MODEL` из `.env` | id модели |

Токены в таблице — prompt + completion по всем запросам способа (у `meta` их два),
отдельно показано, сколько ушло на рассуждение. Время — сумма времени ответов модели.
Результаты: `results/day3_<набор>_<время>.json` (все ответы, рассуждения и сгенерированные промпты)
и `results/day3_<набор>_<время>.md` (таблица, разбивка по задачам и экспертам, ошибки).

Выводы по прогону на `deepseek-v4.1-flash` — в [`results/day3_conclusions.md`](results/day3_conclusions.md).

## День 4: температура

`day4_temperature.py` отправляет одни и те же запросы с `temperature` = 0, 0.7 и 1.2,
каждую комбинацию — 5 раз, проверяет ответы кодом и считает, насколько они расходятся между прогонами.

```powershell
python day4_temperature.py                          # 4 задачи × 3 температуры × 5 прогонов = 60 запросов
python day4_temperature.py --runs 10                # больше прогонов
python day4_temperature.py --temps 0,0.7,1.2,1.8    # другие температуры
python day4_temperature.py --tasks letters,names    # часть задач
python day4_temperature.py --reasoning model        # не выключать рассуждение
python day4_temperature.py --recheck results\day4_<время>.json   # перепроверить сохранённые ответы без запросов
```

| Задача | Тип | Что проверяется |
|---|---|---|
| `letters` | один ответ | сколько раз «а» во фразе «Карл у Клары украл кораллы…» (эталон 12); ответ — строго `{"answer": <целое>}` |
| `days` | один ответ | дней от 01.01.2026 до 01.03.2028 (эталон 790); тот же JSON-формат |
| `names` | генерация | 5 названий кофейни у моря — чистый JSON-массив ровно из 5 строк, без повторов, ≤ 4 слов, каждое только кириллицей |
| `slogan` | генерация | слоган — одна строка, ≤ 8 слов, без кавычек, по-русски |

Эталоны посчитаны кодом. В задачах с одним ответом «формат сломан» и «неверный ответ» считаются
отдельно: число достаётся из ответа мягко, даже если JSON обёрнут в ```` ``` ```` или вокруг есть текст.

Для каждой пары «задача × температура» скрипт печатает и пишет в отчёт:
сколько **разных** ответов из 5 (после нормализации пробелов и регистра), среднюю попарную
**похожесть** текстов (difflib, 100% — все одинаковые), сколько раз **сломался формат**,
сколько **неверных** ответов, для названий — сколько **уникальных** названий набралось за все прогоны
и сколько повторилось в каждом. Отдельной строкой — дал ли `temperature = 0` посимвольно одинаковый ответ.

По умолчанию рассуждение выключено (`reasoning_effort: "none"`): у reasoning-моделей температура может
не влиять на скрытое рассуждение, и сравнение было бы нечистым. `--reasoning model` — не передавать параметр.

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `--temps` | `0,0.7,1.2` | температуры через запятую |
| `--runs` | 5 | прогонов каждой комбинации |
| `--tasks` | все | `letters,days,names,slogan` |
| `--reasoning` | `none` | `none` — выключить рассуждение, `model` — как у модели по умолчанию |
| `--workers` | 4 | параллельных запросов |
| `--timeout` | 120 | таймаут запроса, с |
| `--model` | `LLM_MODEL` из `.env` | id модели |
| `--recheck` | — | без запросов к модели: заново проверить ответы из сохранённого `.json` и перезаписать его и `.md` |

Результаты: `results/day4_<время>.json` (все ответы, токены, проверки) и `results/day4_<время>.md`
(сводная таблица, автоматические наблюдения и все ответы по каждой температуре — это и есть примеры).

Выводы по прогону на `deepseek-v4.1-flash` — в [`results/day4_conclusions.md`](results/day4_conclusions.md).

## Публикация результатов дня

`tasks/publish_day.py` коммитит всё, что не исключено `.gitignore`, в `main`, создаёт ветку
`week_<N>/day_<M>` на том же коммите и отправляет обе на GitHub одной атомарной операцией
(уходят вместе или не уходят вовсе). Промпт для Claude — `tasks/PUBLISH_PROMPT.md`.

```powershell
python tasks\publish_day.py --dry-run            # проверки и список файлов, ничего не меняет
python tasks\publish_day.py                      # последний день из tasks\week_*_day_*.md, спросит подтверждение
python tasks\publish_day.py -m "День 4: <что сделано>"
python tasks\publish_day.py --week 1 --day 4 --message-file msg.txt --yes
python tasks\publish_day.py --no-push            # только локально; потом --push-only
```

До любых изменений скрипт проверяет: текущая ветка `main`, нет незавершённого merge/rebase
и lock-файлов; ветки дня ещё нет ни локально, ни на GitHub; в коммит не попадают `.env`,
ключ из `.env` и файлы больше 20 МБ. Если локальный `main` отстал от GitHub (день отправили
с другого места), а изменённые файлы совпадают, `main` переносится на версию с GitHub без потерь;
при настоящем расхождении скрипт останавливается и ничего не трогает. После push сверяет,
что `main` и ветка дня на GitHub указывают на новый коммит.
